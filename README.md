# หนี้สิน & ตั๋วจำนำ — Debt & Pawn Tracker

แอปติดตามหนี้สิน งวดผ่อน ตั๋วจำนำ และค่าใช้จ่ายประจำ พร้อมแจ้งเตือนก่อนถึงกำหนด — เป็น **PWA (Progressive Web App)** ล้วนๆ ไม่มีส่วนที่เป็นแอป native/Capacitor แล้ว เปิดผ่านเบราว์เซอร์มือถือแล้วกด "เพิ่มไปยังหน้าจอโฮม" ก็ใช้งานได้เหมือนแอปจริง มีไอคอน เปิดแบบเต็มจอ และรับ push notification ได้

```
debt-pawn-tracker/
  app/       ← เว็บแอป (PWA): HTML/CSS/JS ธรรมดา + service worker
  backend/   ← PHP REST API + MySQL schema
```

ระบบเป็นแบบ **ผู้ใช้คนเดียว** (single-user) — ไม่มีสมัครสมาชิก ไม่มี username/password ไม่มี Google Sign-in แค่ตั้ง PIN 4-6 หลักครั้งแรกที่เปิดแอป แล้วใช้ PIN นั้นปลดล็อกทุกครั้งต่อไป

## 1. ตั้งค่า Backend (PHP + MySQL)

1. สมัคร hosting ฟรีที่รองรับ PHP + MySQL (เช่น InfinityFree, GoogieHost — ทั้งสองเจ้าใช้โครงสร้างพื้นฐานเดียวกัน) แล้วสร้างเว็บไซต์ใหม่ (จะได้โดเมนแบบ `yourname.infinityfreeapp.com` หรือ `yourname.42web.io`)
2. ไปที่ **MySQL Databases** ในควบคุมพาเนล สร้างฐานข้อมูลใหม่ จดค่า: hostname, database name, username, password
3. เปิด **phpMyAdmin** จากพาเนล → เลือกฐานข้อมูล → แท็บ **Import** → อัปโหลดไฟล์ [`backend/schema.sql`](backend/schema.sql) → Go
4. คัดลอก `backend/config/config.example.php` เป็น `backend/config/config.php` (ไฟล์นี้ถูก gitignore ไว้ ไม่มีทางหลุดขึ้น git repo โดยไม่ตั้งใจ) แล้วแก้ไข `backend/config/config.php`:
   - ใส่ `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` จากขั้นตอนที่ 2
   - สร้างค่าสุ่มสำหรับ `JWT_SECRET` และ `CRON_SECRET` ด้วยคำสั่ง:
     ```bash
     php -r "echo bin2hex(random_bytes(32));"
     ```
     (รันบนเครื่องไหนก็ได้ที่มี PHP หรือใช้เว็บ random string generator ก็ได้ ขอแค่เป็นสตริงยาวสุ่มไม่ซ้ำใคร)
   - ใส่ `ALLOWED_ORIGINS` ให้ตรงกับโดเมนที่จะ deploy เว็บแอป (ดูข้อ 3)
5. อัปโหลดทั้งโฟลเดอร์ `backend/` ขึ้นไปที่ `htdocs/` ผ่าน FTP (FileZilla) หรือ File Manager ในพาเนล ให้โครงสร้างเป็น `htdocs/backend/api/...`, `htdocs/backend/config/...` เป็นต้น
6. ทดสอบว่า backend ทำงาน: เปิด `https://yourname.infinityfreeapp.com/backend/api/auth/login.php` ด้วย POST (ใช้ Postman หรือ curl) ส่ง `{"pin":"1234"}` — ควรได้ JWT token กลับมา

> **หมายเหตุสำคัญ**: hosting ฟรีบาง instance **บล็อกการเชื่อมต่อออก (outbound cURL)** ไปยังเซิร์ฟเวอร์ภายนอก ซึ่งจำเป็นสำหรับการยิง push notification ไป Firebase (`backend/lib/FcmSender.php` ใช้ cURL เรียก `oauth2.googleapis.com` และ `fcm.googleapis.com`) ถ้าทดสอบแล้วส่ง push ไม่ได้ (endpoint cron คืนค่า `sent:0` ตลอด) ให้ลอง hosting ฟรีทางเลือก หรือย้าย endpoint cron ไปรันบน Render.com free tier (รองรับ PHP ผ่าน Docker)

## 2. ตั้งค่า Cron (cron-job.org)

1. สมัครบัญชีฟรีที่ [cron-job.org](https://cron-job.org)
2. สร้าง cronjob ใหม่:
   - URL: `https://yourname.infinityfreeapp.com/backend/api/cron/check-due.php`
   - Method: `POST`
   - Schedule: ทุกวัน เวลา 08:00 (ตามต้องการ)
   - Headers: เพิ่ม `X-Cron-Secret: <ค่า CRON_SECRET ที่ตั้งไว้ในขั้นตอนที่แล้ว>`
3. บันทึกและกด "Test run" เพื่อดูว่าได้ `{"ok":true,...}` กลับมา

## 3. Deploy เว็บแอป (PWA) + ทำให้ติดตั้งลงมือถือได้

เว็บแอปเป็นไฟล์ static ล้วน (`app/www/`) — เอาไปวางบน hosting ไหนก็ได้ที่เสิร์ฟไฟล์ static ได้ (ใช้ hosting เดียวกับ backend ก็ได้ วางคนละโฟลเดอร์ เช่น `htdocs/app/`)

1. แก้ [`app/www/js/api.js`](app/www/js/api.js) บรรทัด `BASE_URL` (นอก localhost) ให้ชี้ไปที่ backend จริงของคุณ:
   ```js
   : 'https://yourname.infinityfreeapp.com/backend/api';
   ```
2. อัปโหลดทั้งโฟลเดอร์ `app/www/` ขึ้น hosting (FTP หรือ File Manager) เช่นที่ `htdocs/app/`
3. แก้ `ALLOWED_ORIGINS` ใน `backend/config/config.php` ให้มีโดเมนจริงของเว็บแอป (เช่น `https://yourname.infinityfreeapp.com`)
4. เปิด URL เว็บแอปในมือถือ (Chrome บน Android แนะนำที่สุด) → เมนู (จุดสามจุด) → **"เพิ่มไปยังหน้าจอโฮม"** หรือ **"ติดตั้งแอป"** → จะได้ไอคอนแอปจริงบนมือถือ เปิดแบบเต็มจอเหมือนแอป native ไม่ต้องผ่าน Play Store

> บน iPhone (Safari): แชร์ (ไอคอนสี่เหลี่ยมมีลูกศร) → "เพิ่มไปยังหน้าจอโฮม" — ต้อง iOS 16.4 ขึ้นไปถึงจะได้ push notification ด้วย

## 4. ตั้งค่า Firebase (สำหรับ push notification แบบ Web Push)

1. ไปที่ [Firebase Console](https://console.firebase.google.com) → สร้างโปรเจกต์ใหม่ (ฟรี, Spark plan)
2. เพิ่มแอปแบบ **Web** (ไอคอน `</>`) — ตั้งชื่ออะไรก็ได้ ไม่ต้องติ๊ก Firebase Hosting
3. จะได้ค่า config (apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId) — เอาไปใส่ใน [`app/www/firebase-config.js`](app/www/firebase-config.js) แทนค่า placeholder ทั้งหมด
4. ไปที่ **Project Settings > Cloud Messaging** แท็บ → เลื่อนไปหา **Web configuration** → กด **Generate key pair** → คัดลอกค่า (VAPID key) มาใส่ที่ `FIREBASE_VAPID_KEY` ใน `firebase-config.js`
5. ไปที่ **Project Settings > Service Accounts** → กด **Generate new private key** → จะได้ไฟล์ JSON → อัปโหลดไปที่ `backend/config/firebase-service-account.json` บน hosting (**อย่า** เผยแพร่ไฟล์นี้ที่ไหนที่เข้าถึงได้สาธารณะ — ต่างจาก `firebase-config.js` ที่เป็นค่า public ปลอดภัยที่จะ commit ขึ้น git)
6. แก้ `FCM_PROJECT_ID` ใน `backend/config/config.php` ให้ตรงกับ Project ID ใน Firebase

เมื่อผู้ใช้ตั้ง PIN สำเร็จครั้งแรก แอปจะขอ permission แจ้งเตือนจากเบราว์เซอร์อัตโนมัติ (`Notification.requestPermission()`) แล้วลงทะเบียน token กับ backend ให้เอง — ถ้ายังไม่ได้ตั้งค่า Firebase (ค่ายังเป็น placeholder) ระบบจะข้ามส่วนนี้ไปเงียบๆ ไม่ error

## 5. Flow การเข้าสู่ระบบ

ระบบผู้ใช้คนเดียว ไม่มีบัญชี ไม่มีรหัสผ่าน มีแค่ PIN:

1. **เปิดแอปครั้งแรก** → หน้าตั้ง PIN ให้กรอก **2 รอบ** (กรอกครั้งแรก แล้วกรอกซ้ำเพื่อยืนยัน ถ้าไม่ตรงกันจะให้เริ่มใหม่) — PIN นี้จะกลายเป็น PIN ของแอปไปตลอด
2. **เปิดแอปครั้งต่อไป** (ในเครื่อง/เบราว์เซอร์เดิม) → ขึ้นแค่หน้า **ใส่ PIN** อย่างเดียว ไม่ต้องตั้งใหม่
3. ใส่ PIN ผิด 5 ครั้งติด → ล็อก 30 วินาที

> **ไม่มีระบบ "ลืม PIN"** — เพราะไม่ได้เก็บเบอร์โทร/อีเมลของผู้ใช้ไว้เลย (ตัดออกเพื่อความเรียบง่ายตามที่ขอ) ถ้าลืม PIN จริงๆ ทางแก้คือล้างข้อมูลฐานข้อมูล `users` แล้วเริ่มตั้งใหม่ (จะเสียข้อมูลหนี้/ตั๋วจำนำเดิมไปด้วยถ้าลบทั้งฐานข้อมูล ควรลบแค่แถวใน `users` ถ้าอยากเก็บข้อมูลอื่นไว้)

### API endpoints
- `POST /api/auth/login.php` — ส่ง `{pin}` ครั้งแรกจะสร้างบัญชี ครั้งต่อไปคือตรวจ PIN
- `POST /api/auth/register-token.php` — ลงทะเบียน FCM token สำหรับ push notification

## 6. ตั๋วจำนำ: หมวดหมู่ และกฎต่อดอกของ "เครื่องประดับ"

หน้าเพิ่มตั๋วจำนำมีหมวดหมู่ให้เลือก: 💍 เครื่องประดับ, 🚗 รถ, 📱 อุปกรณ์อิเล็กทรอนิก, 📦 อื่นๆ

**กฎพิเศษเฉพาะหมวด "เครื่องประดับ"**: ต่อดอกได้สูงสุด **4 เดือน** นับจากวันที่รับตั๋ว หลังจากนั้นเข้าสู่ **เดือนที่ 5 ซึ่งเป็นกำหนดสุดท้าย**:

1. ต่อดอกได้ตามปกติ (เลือกระยะเวลาได้อิสระ) จนครบ 4 ครั้ง — ปุ่มจะขึ้น "ต่อดอกแล้ว x/4 ครั้ง" ให้ดูสถานะ
2. พอครบ 4 ครั้ง ปุ่มจะเปลี่ยนเป็น **"เลือกวันชำระ"** แทน — เลือกวันที่ตั้งใจจะไปไถ่ถอนได้ แต่ต้องไม่เกินวันครบกำหนดสุดท้าย (วันที่รับตั๋ว + 5 เดือน) ระบบจะแจ้งเตือนแบบปกติในช่วงนี้
3. เมื่อเลือกวันชำระแล้ว (ใช้สิทธิ์ครั้งสุดท้ายไปแล้ว) จะเหลือแค่ปุ่ม "ไถ่ถอนแล้ว" อย่างเดียว
4. ถ้าถึงวันครบกำหนดสุดท้าย (เดือนที่ 5) แล้วยังไม่ไถ่ถอน — badge จะเปลี่ยนเป็น **สีแดง "⚠️ ใกล้ขาดจำนำ"** และ push notification จะแจ้งเตือนทุกวัน (ไม่รอรอบเหมือนปกติ) ว่าใกล้เสียสิทธิ์ไถ่ถอนแล้ว

หมวดอื่น (รถ, อุปกรณ์อิเล็กทรอนิก, อื่นๆ) ต่อดอกได้ไม่จำกัดจำนวนครั้งเหมือนเดิม ไม่มีกำหนดสุดท้ายบังคับ

## 7. ค่าใช้จ่ายประจำต่อเดือน & หน้าแรกแบบรายงาน

- **ค่าใช้จ่ายประจำต่อเดือน** (`recurring_expenses`): เพิ่มได้จากปุ่ม + ในหน้าแรก หรือจากหน้า "ค่าใช้จ่ายประจำ" เอง (กดเข้าจากการ์ดในหน้าแรก) แต่ละรายการกด "บันทึกว่าจ่ายแล้ว" ได้ทุกเดือน — พอขึ้นเดือนใหม่จะกลับเป็นสถานะยังไม่จ่ายให้อัตโนมัติ มี 2 แบบ (`expense_type`):
  - **ยอดคงที่ทุกเดือน (`fixed`)** — เช่น ค่าเช่า, ค่าเลี้ยงดูบุตร ยอดเท่าเดิมทุกเดือน กรอกยอดครั้งเดียวตอนเพิ่มรายการ
  - **ไม่คงที่ ต้องจ่ายทุกเดือน (`variable`)** — เช่น ค่าน้ำ ค่าไฟ ค่าเน็ต ยอดเปลี่ยนทุกเดือน ตอนกด "บันทึกว่าจ่ายแล้ว" ต้องกรอกยอดจริงของเดือนนั้น (เก็บประวัติไว้ในตาราง `expense_payments` แยกตามเดือน) หน้ารายการ/หน้าแรกจะใช้ยอดล่าสุดที่เคยจ่ายเป็นตัวประมาณการก่อนจ่ายจริง
  - **ค่าใช้จ่ายแบบไม่มีกำหนดระยะเวลา/จ่ายเป็นก้อน** (เช่น ยืมเงินเพื่อนมาจ่าย แล้วทยอยคืนเป็นก้อนๆ ไม่ตายตัวว่าเดือนไหน) — ไม่ได้ทำเป็นระบบแยกต่างหาก เพราะพฤติกรรมเหมือนหนี้สินอยู่แล้ว (มียอดคงเหลือ จ่ายคืนเมื่อไหร่ก็ได้ จ่ายบางส่วนหรือหมดทีเดียวก็ได้) ให้ใช้ฟีเจอร์ **หนี้สิน** (`debts` แบบ `lump_sum`) แทน
- **หน้าแรกเป็นหน้ารายงานในตัว**: แสดงสรุป 4 ยอด — ยอดหนี้สิน, ยอดตั๋วจำนำ, ค่าใช้จ่ายประจำต่อเดือน (ยอดรวมคงที่), และ**ยอดที่ต้องชำระเดือนนี้** (ลดลงทันทีที่กดบันทึกจ่ายแต่ละรายการ) พร้อมรายการที่ต้องชำระและปุ่มบันทึกจ่ายในตัว
- **แจ้งเตือนรายคาบสำหรับตั๋วจำนำ**: ตั๋วแต่ละใบเก็บ `period_unit`/`period_value` ไว้ (ตอนสร้างและตอนต่อดอกแต่ละครั้ง) แล้ว `cron/check-due.php` ใช้ค่านี้คำนวณว่าจะแจ้งเตือนซ้ำทุกกี่วัน แทนที่จะแจ้งทุกวัน เช่น เลือก "7 วัน" แจ้งเตือนแล้วยังไม่ต่อดอก ระบบจะรอครบ 7 วันถึงแจ้งเตือนรอบต่อไป
- **Push notification ครอบคลุมทั้ง 3 อย่าง**: งวดหนี้, ตั๋วจำนำ (รวมกรณีฉุกเฉินเดือนที่ 5 ของเครื่องประดับ), และค่าใช้จ่ายประจำ

### API endpoints
- `GET/POST /api/expenses/index.php` — รายการ/เพิ่มค่าใช้จ่ายประจำ (`expense_type`: `fixed` ต้องส่ง `amount`, `variable` ไม่ต้อง)
- `PATCH /api/expenses/mark-paid.php` — บันทึกว่าจ่ายค่าใช้จ่ายประจำของเดือนนี้แล้ว (ส่ง `amount` ด้วยถ้าเป็น `variable`)
- `DELETE /api/expenses/delete.php` — ลบค่าใช้จ่ายประจำ
- `GET /api/dashboard/report.php` — ข้อมูลสรุปหน้าแรกทั้งหมด (4 ยอด + รายการที่ต้องชำระเดือนนี้)

## 8. ทดสอบก่อนใช้งานจริง

- [ ] เปิดแอปครั้งแรก ตั้ง PIN (กรอก 2 รอบ) → เข้าหน้าแรกได้
- [ ] ปิดแอปแล้วเปิดใหม่ → ขึ้นแค่หน้าใส่ PIN ไม่ใช่หน้าตั้งใหม่
- [ ] ใส่ PIN ผิด 5 ครั้ง → ล็อก 30 วินาที
- [ ] "เพิ่มไปยังหน้าจอโฮม" บนมือถือจริง → ได้ไอคอนแอป เปิดแบบเต็มจอ
- [ ] เพิ่มหนี้ใหม่ → เช็คว่าสร้างงวดผ่อน 3 งวดถัดไปให้อัตโนมัติ
- [ ] กด "บันทึกว่าจ่ายแล้ว" → ยอดคงเหลือลดลงถูกต้อง
- [ ] เพิ่มตั๋วจำนำหมวด "เครื่องประดับ" → ต่อดอกครบ 4 ครั้ง → ปุ่มเปลี่ยนเป็น "เลือกวันชำระ" ตามที่อธิบายในข้อ 6 → ทดสอบว่าเลือกวันเกินกำหนดสุดท้ายไม่ได้
- [ ] เพิ่มค่าใช้จ่ายประจำแบบ "ยอดคงที่ทุกเดือน" → เช็คว่าไปโผล่ในหน้าแรกถูกต้อง และยอด "ต้องชำระเดือนนี้" ลดลงเมื่อบันทึกจ่ายแล้ว
- [ ] เพิ่มค่าใช้จ่ายประจำแบบ "ไม่คงที่ ต้องจ่ายทุกเดือน" (เช่น ค่าไฟ) → กด "บันทึกว่าจ่ายแล้ว" ต้องขึ้นช่องกรอกยอดจริงก่อนถึงจะยืนยันได้ → เช็คว่ายอดที่กรอกไปโผล่เป็น "ล่าสุด" ในหน้ารายการ
- [ ] ตั้งค่า Firebase ครบแล้ว → เปิดแอปครั้งแรกควรมี prompt ขอ permission แจ้งเตือน
- [ ] รอ cron รันจริง (หรือกด Test run ใน cron-job.org) แล้วดูว่า push แจ้งเตือนมาถึงเครื่องจริงไหม โดยเฉพาะ**ตอนปิดแอป/ปิดจอ** — เช็คว่าตั๋วจำนำแจ้งเตือนซ้ำตามรอบที่เลือกไว้ ไม่ใช่ทุกวัน ยกเว้นตั๋วเครื่องประดับที่เลยกำหนดสุดท้ายแล้ว (ต้องแจ้งทุกวัน)

## ข้อควรระวัง

- Hosting ฟรีอาจไม่เสถียร 100% และบางเจ้าบล็อก outbound cURL (ดูหมายเหตุในข้อ 1) — เหมาะกับ personal use ถ้าจะใช้จริงจังควรมีแผนย้ายไป hosting เสียเงินในอนาคต
- Push notification บน iOS ต้อง "เพิ่มไปยังหน้าจอโฮม" ก่อนถึงจะใช้ได้ (เปิดผ่าน Safari tab เฉยๆ ไม่ได้) และต้อง iOS 16.4 ขึ้นไป
- Android บางยี่ห้อ (Xiaomi, Huawei, OPPO) มี battery optimization ที่ block background process ต้องเข้าไปปิด optimization สำหรับเบราว์เซอร์/แอปนี้เอง ไม่งั้น push อาจไม่มาตอนไม่ได้เปิดหน้าจอนานๆ
- ไฟล์ `backend/config/config.php` และ `backend/config/firebase-service-account.json` มีความลับ (DB password, JWT secret, private key) — อย่าอัปโหลดขึ้น public repo หรือแชร์ให้ใคร (ต่างจาก `app/www/firebase-config.js` ซึ่งเป็นค่า public ที่ตั้งใจให้อยู่ใน client code)
- ไม่มีระบบกู้คืน PIN — ลืมแล้วต้องเข้าไปแก้ที่ฐานข้อมูลเอง (ดูข้อ 5)
