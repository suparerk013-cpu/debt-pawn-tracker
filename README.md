# หนี้สิน & ตั๋วจำนำ — Debt & Pawn Tracker

แอปติดตามหนี้สิน งวดผ่อน ตั๋วจำนำ และค่าใช้จ่ายประจำ พร้อมแจ้งเตือนก่อนถึงกำหนด — เป็น **PWA (Progressive Web App)** เปิดผ่านเบราว์เซอร์มือถือแล้วกด "เพิ่มไปยังหน้าจอโฮม" ก็ใช้งานได้เหมือนแอปจริง มีไอคอน เปิดแบบเต็มจอ

```
debt-pawn-tracker/
  app/www/        ← เว็บแอป (PWA) ทั้งหมด: HTML/CSS/JS ธรรมดา + service worker
  app/dev-server.js ← static server เอาไว้ทดสอบในเครื่อง (ไม่มี backend ให้รัน)
  firestore.rules  ← กฎความปลอดภัยของฐานข้อมูล
  firebase.json, .firebaserc ← ตั้งค่า deploy ขึ้น Firebase Hosting
```

**ไม่มี backend เป็นของตัวเองแล้ว** — เบราว์เซอร์คุยกับ **Firebase (Firestore)** ตรงๆ ไม่ต้องหา PHP/MySQL hosting เอง ไม่ต้องกังวลเรื่อง hosting ฟรีล่ม/ติด CAPTCHA แบบเดิมอีกต่อไป เพราะ Firebase ให้ hosting + database ฟรีในตัว (โปรเจกต์ `debt-pawn-tracker-cc106`)

ระบบมี **ผู้ใช้คงที่ 2 คน** (`not` และ `lek`) — ไม่มีรหัสผ่าน เข้าแอปแค่พิมพ์ชื่อผู้ใช้แล้วเข้าได้เลย `not` เป็นแอดมิน กดสลับไปดู/แก้ไขข้อมูลของ `lek` ได้จากปุ่มในหน้าแรก

> **ข้อจำกัดที่ต้องรู้**: เวอร์ชันนี้ไม่มี push notification ไปเครื่องตอนปิดแอปแล้ว (ของเดิมต้องใช้ Cloud Functions ซึ่ง Firebase บังคับให้ผูกบัตรเครดิต/เปิดแพลน Blaze ก่อน — ตัดสินใจไม่เปิดเพื่อเลี่ยงเรื่องบัตรเครดิต) แทนที่ด้วย **กระดิ่งแจ้งเตือนในแอป** ที่คำนวณสดทุกครั้งที่เปิดแอป/กดกระดิ่ง (เช็คตามกฎเดิมทุกอย่าง แค่ไม่เด้งเตือนตอนแอปปิดอยู่)

## 1. โครงสร้างข้อมูลใน Firestore

- **`users/{username}`** — เอกสาร ID คือชื่อผู้ใช้ (`not`, `lek`) มี `is_admin`, `warn_days` ผู้ใช้ทั้งสองถูกสร้างอัตโนมัติตอนพิมพ์ชื่อเข้าแอปครั้งแรก ไม่ต้องสร้างเองในคอนโซล
- **`debts/{id}`** — หนี้แต่ละก้อน มี `installments` เป็น array ฝังอยู่ในเอกสารเดียวกันเลย (ไม่ใช่ subcollection) เพื่อลดจำนวนการอ่านข้อมูล
- **`pawns/{id}`** — ตั๋วจำนำแต่ละใบ
- **`expenses/{id}`** — ค่าใช้จ่ายประจำ มี `payments` เป็น map ฝังอยู่ในเอกสาร คีย์เป็นเดือน `'YYYY-MM'`
- ไม่มี collection สำหรับ notification — กระดิ่งคำนวณจากข้อมูลสดทุกครั้ง ไม่เก็บประวัติถาวร

ทุกเอกสารมีฟิลด์ `user_id` (ค่าคือ `'not'` หรือ `'lek'`) เอาไว้กรองข้อมูลของแต่ละคน — นี่คือกลไกแยกข้อมูลทั้งหมด ไม่มีการใช้ Firebase Auth UID จริงจังเป็นตัวแบ่งข้อมูล (ดูหัวข้อความปลอดภัยด้านล่าง)

### ความปลอดภัย (ข้อควรระวัง)

`firestore.rules` อนุญาตให้ **ใครก็ตามที่ล็อกอินแบบ anonymous** (ซึ่งแอปทำให้อัตโนมัติตอนเปิดหน้าเว็บ ไม่ต้องกดอะไร) อ่าน/เขียนข้อมูลได้ทั้งหมด — เทียบเท่ากับความปลอดภัยของระบบเดิมที่ "พิมพ์ชื่อผู้ใช้ก็เข้าได้เลยไม่มีรหัสผ่าน" ทุกประการ **เหมาะกับใช้ในวงจำกัด (ครอบครัว/คู่รัก) เท่านั้น** ไม่ควรแชร์ลิงก์แอปให้คนนอก เพราะใครก็ตามที่รู้ URL จะเข้าดู/แก้ข้อมูลได้ (เหมือนระบบ PIN/username เดิมที่ไม่มีการยืนยันตัวตนจริงอยู่แล้ว)

## 2. รันทดสอบในเครื่อง

```bash
node app/dev-server.js
```
เปิด `http://localhost:5522` — ไฟล์เป็น static ล้วนๆ แต่ข้อมูลจริงจะไปที่ Firestore ของโปรเจกต์ `debt-pawn-tracker-cc106` เลย (ไม่มี emulator/mock แยกต่างหาก เพราะ Firestore ฟรีอยู่แล้วไม่มีต้นทุนต้อง mock)

---

## 3. Deploy ขึ้น Firebase Hosting

ต้องมี [Firebase CLI](https://firebase.google.com/docs/cli) (ใช้ผ่าน `npx` ก็ได้ไม่ต้องติดตั้งถาวร):

```bash
npx firebase-tools login          # ล็อกอินด้วยบัญชี Google ที่สร้างโปรเจกต์ debt-pawn-tracker-cc106 ไว้ (ครั้งแรกครั้งเดียว)
npx firebase-tools deploy         # deploy ทั้ง Hosting และ Firestore rules
```

Deploy เสร็จจะได้ลิงก์ประมาณ `https://debt-pawn-tracker-cc106.web.app` — เปิดจากมือถือได้เลย ไม่ต้องหา hosting เจ้าอื่นอีก อยากอัปเดตแอปทีหลังก็แก้โค้ดใน `app/www/` แล้วรัน `npx firebase-tools deploy` ซ้ำ

## 4. Flow การเข้าสู่ระบบ และผู้ใช้ 2 คน

ผู้ใช้มี 2 คนตายตัว (`not` = แอดมิน, `lek` = ผู้ใช้ทั่วไป) ไม่มีการสมัครสมาชิกเพิ่ม ไม่มีรหัสผ่าน:

1. **เปิดแอป** → พิมพ์ `not` หรือ `lek` → กด "เข้าแอป" → เข้าหน้าแรกทันที (ถ้าเป็นครั้งแรกที่มีคนพิมพ์ชื่อนี้ ระบบจะสร้างผู้ใช้นี้ให้อัตโนมัติใน Firestore)
2. **เปิดแอปครั้งต่อไป** (เครื่อง/เบราว์เซอร์เดิม) → เข้าหน้าแรกเลยไม่ต้องพิมพ์ชื่อซ้ำ จนกว่าจะกด "ออกจากระบบ"
3. **สลับผู้ใช้ (เฉพาะแอดมิน `not`)**: กดไอคอน ⇄ ที่หน้าแรก → เลือกชื่อผู้ใช้ที่จะดู → แก้ไข/เพิ่ม/ลบข้อมูลของคนนั้นได้เต็มสิทธิ์ — หัวข้อจะโชว์ "(กำลังดูข้อมูลของคนอื่น)" กำกับไว้

ข้อมูลของแต่ละคนแยกกันผ่านฟิลด์ `user_id` — `lek` เข้าเองจะไม่เห็นและสลับไปดูของ `not` ไม่ได้ (สลับได้เฉพาะฝั่งแอดมิน)

## 5. ตั๋วจำนำ: หมวดหมู่ และกฎต่อดอกของ "เครื่องประดับ"

หน้าเพิ่มตั๋วจำนำมีหมวดหมู่ให้เลือก: 💍 เครื่องประดับ, 🚗 รถ, 📱 อุปกรณ์อิเล็กทรอนิก, 📦 อื่นๆ

**กฎพิเศษเฉพาะหมวด "เครื่องประดับ"**: ต่อดอกได้สูงสุด **4 เดือน** นับจากวันที่รับตั๋ว หลังจากนั้นเข้าสู่ **เดือนที่ 5 ซึ่งเป็นกำหนดสุดท้าย**:

1. ต่อดอกได้ตามปกติ (เลือกระยะเวลาได้อิสระ) จนครบ 4 ครั้ง — ปุ่มจะขึ้น "ต่อดอกแล้ว x/4 ครั้ง" ให้ดูสถานะ
2. พอครบ 4 ครั้ง ปุ่มจะเปลี่ยนเป็น **"เลือกวันชำระ"** แทน — เลือกวันที่ตั้งใจจะไปไถ่ถอนได้ แต่ต้องไม่เกินวันครบกำหนดสุดท้าย (วันที่รับตั๋ว + 5 เดือน)
3. เมื่อเลือกวันชำระแล้ว (ใช้สิทธิ์ครั้งสุดท้ายไปแล้ว) จะเหลือแค่ปุ่ม "ไถ่ถอนแล้ว" อย่างเดียว
4. ถ้าถึงวันครบกำหนดสุดท้าย (เดือนที่ 5) แล้วยังไม่ไถ่ถอน — badge จะเปลี่ยนเป็น **สีแดง "⚠️ ใกล้ขาดจำนำ"** และจะโผล่เป็นรายการด่วนในกระดิ่งแจ้งเตือนทุกครั้งที่เปิดแอป

หมวดอื่น (รถ, อุปกรณ์อิเล็กทรอนิก, อื่นๆ) ต่อดอกได้ไม่จำกัดจำนวนครั้งเหมือนเดิม ไม่มีกำหนดสุดท้ายบังคับ

> กฎนี้บังคับใช้ที่ฝั่ง client (ในเบราว์เซอร์) เท่านั้น เพราะไม่มี server คอยเช็คซ้ำอีกชั้นแล้ว — เหมาะกับแอปที่ใช้กันเองในครอบครัวที่ไว้ใจกัน ไม่ได้ออกแบบมาป้องกันคนตั้งใจแก้ข้อมูลผ่าน DevTools

## 6. ค่าใช้จ่ายประจำต่อเดือน

มี 2 แบบ (`expense_type`):
- **ยอดคงที่ทุกเดือน (`fixed`)** — เช่น ค่าเช่า, ค่าเลี้ยงดูบุตร ยอดเท่าเดิมทุกเดือน กรอกยอดครั้งเดียวตอนเพิ่มรายการ
- **ไม่คงที่ ต้องจ่ายทุกเดือน (`variable`)** — เช่น ค่าน้ำ ค่าไฟ ค่าเน็ต ยอดเปลี่ยนทุกเดือน ตอนกด "บันทึกว่าจ่ายแล้ว" ต้องกรอกยอดจริงของเดือนนั้น หน้ารายการ/หน้าแรกจะใช้ยอดล่าสุดที่เคยจ่ายเป็นตัวประมาณการก่อนจ่ายจริง
- **ค่าใช้จ่ายแบบไม่มีกำหนดระยะเวลา/จ่ายเป็นก้อน** (เช่น ยืมเงินเพื่อนมาจ่าย แล้วทยอยคืนเป็นก้อนๆ) — ไม่ได้ทำเป็นระบบแยกต่างหาก เพราะพฤติกรรมเหมือนหนี้สินอยู่แล้ว ให้ใช้ฟีเจอร์ **หนี้สิน** แทน

แต่ละรายการกด "บันทึกว่าจ่ายแล้ว" ได้ทุกเดือน — พอขึ้นเดือนใหม่จะกลับเป็นสถานะยังไม่จ่ายให้อัตโนมัติ (เช็คจากว่ามีประวัติจ่ายของเดือนปัจจุบันหรือยัง ไม่ได้ใช้ flag ที่ต้องรีเซ็ตเอง)

## 7. ตั้งค่าแต่ละรายการหนี้ และกระดิ่งแจ้งเตือน

**ตั้งค่าหนี้ (กดไอคอนเฟืองที่หน้ารายละเอียดหนี้)**:
- **แก้ไข**: ปรับชื่อ, ยอดหนี้ทั้งหมด, ยอดคงเหลือ, วันครบกำหนดจ่าย, ยอดผ่อนต่อเดือน — ถ้าปรับ "ยอดผ่อนต่อเดือน" งวดที่ยังไม่จ่ายทั้งหมดจะถูกปรับยอดตามใหม่ทันที
- **ปิดหนี้**: ใช้เมื่อชำระครบแล้ว โดยไม่อยากลบประวัติทิ้ง — หนี้จะหายจากหน้ารายการแต่ข้อมูลยังอยู่ใน Firestore
- **ลบหนี้**: ลบถาวรทั้งหนี้และงวดผ่อนทั้งหมด กู้คืนไม่ได้

**กระดิ่งแจ้งเตือน (มุมขวาบนหน้าแรก)**: แสดงรายการที่ใกล้ถึงกำหนด/เลยกำหนดแล้ว (งวดหนี้, ตั๋วจำนำ, ค่าใช้จ่ายประจำ) คำนวณสดทุกครั้งที่เปิด ไม่ใช่การแจ้งเตือนแบบ push — มีจุดสีเขียวกำกับรายการที่ยังไม่อ่าน (จำสถานะ "อ่านแล้ว" แบบรายวันไว้ในเครื่อง ไม่ได้เก็บถาวร) กดรายการเพื่อทำเครื่องหมายว่าอ่านแล้ว หรือกด "อ่านทั้งหมด"

## 8. ทดสอบก่อนใช้งานจริง

- [ ] เปิดแอป พิมพ์ชื่อ `not` หรือ `lek` → เข้าหน้าแรกได้ทันที
- [ ] พิมพ์ชื่อที่ไม่มีในระบบ → ขึ้น "ไม่พบผู้ใช้นี้"
- [ ] ปิดแอปแล้วเปิดใหม่ → เข้าหน้าแรกเลย ไม่ต้องพิมพ์ชื่อซ้ำ
- [ ] ล็อกอินด้วย `not` → กดไอคอน ⇄ สลับไปดู `lek` → เพิ่ม/แก้/ลบข้อมูลของ `lek` ได้ → สลับกลับมาเช็คว่าข้อมูลแยกกันจริง
- [ ] ล็อกอินด้วย `lek` โดยตรง → ไม่มีปุ่มสลับผู้ใช้ให้เห็น
- [ ] กดกระดิ่งแจ้งเตือน → เห็นรายการที่ใกล้/เลยกำหนด, กดอ่าน/อ่านทั้งหมดได้
- [ ] เปิดรายละเอียดหนี้ → กดไอคอนเฟือง → แก้ยอดผ่อนต่อเดือน → เช็คว่างวดที่ยังไม่จ่ายเปลี่ยนยอดตามจริง
- [ ] ปิดหนี้ 1 รายการ → หายจากหน้ารายการหนี้และยอดรวมหน้าแรก
- [ ] ลบหนี้ 1 รายการ → หายไปถาวรพร้อมงวดผ่อน
- [ ] เพิ่มหนี้ใหม่ → สร้างงวดผ่อน 3 งวดถัดไปให้อัตโนมัติ
- [ ] เพิ่มตั๋วจำนำหมวด "เครื่องประดับ" → ต่อดอกครบ 4 ครั้ง → ปุ่มเปลี่ยนเป็น "เลือกวันชำระ" ตามข้อ 5
- [ ] เพิ่มค่าใช้จ่ายแบบ "ไม่คงที่" → กด "บันทึกว่าจ่ายแล้ว" ต้องกรอกยอดจริงก่อน
- [ ] "เพิ่มไปยังหน้าจอโฮม" บนมือถือจริง → ได้ไอคอนแอป เปิดแบบเต็มจอ
- [ ] Deploy ขึ้น Firebase Hosting แล้วเปิดจากมือถือจริงได้

## ข้อควรระวัง

- **ไม่มี push notification เมื่อแอปปิดอยู่** (ดูคำอธิบายด้านบน) — ถ้าอยากได้ฟีเจอร์นี้ในอนาคต ต้องเปิดแพลน Blaze ของ Firebase (ผูกบัตรเครดิต แต่การใช้งานระดับนี้จะไม่มีการเก็บเงินจริงเพราะอยู่ในโควต้าฟรี) แล้วเพิ่ม Cloud Function แบบตั้งเวลา
- **ไม่มีรหัสผ่านป้องกันการเข้าแอป** — ใครก็ตามที่รู้ URL และชื่อผู้ใช้ (`not`/`lek`) เข้าดูข้อมูลได้ทันที เหมาะใช้ในอุปกรณ์/วงคนที่ไว้ใจกันเท่านั้น ไม่ควรแชร์ลิงก์ให้คนนอก
- โควต้าฟรีของ Firestore/Hosting นับแยกตามโปรเจกต์ (ไม่ได้แชร์กับโปรเจกต์ Firebase อื่นในบัญชีเดียวกัน) การใช้งานระดับแอปส่วนตัวแบบนี้ไม่มีทางเกินโควต้าฟรีอยู่แล้ว
