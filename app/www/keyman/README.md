# สมุดงานประกันคีย์แมน (PWA)

เว็บแอปสำหรับตัวแทนประกันชีวิต ใช้คำนวณเบี้ยประกันคีย์แมนที่เหมาะกับลูกค้านิติบุคคล
และตรวจว่าโครงสร้างที่เสนอสอดคล้องกับหลักเกณฑ์ของกรมสรรพากรหรือไม่ — ยก Excel เดิม 8 ชีต
ขึ้นเว็บทั้งแผง แถวเดิม คอลัมน์เดิม ลำดับเดิม

**เปิดใช้งานออนไลน์:** https://debt-pawn-tracker-cc106.web.app/keyman/
(เปิดจากมือถือแล้วกด "เพิ่มไปยังหน้าจอโฮม" ใช้งานได้เหมือนแอปจริง และใช้ได้ครบแม้ไม่มีเน็ต)

---

## 1. โครงไฟล์

```
app/www/keyman/
  index.html                 โครงหน้าเดียว โหลดสคริปต์ทั้งหมด
  css/app.css                ธีมสว่าง/มืดผ่าน CSS custom properties
  js/tax-tables.js           ตารางอัตราภาษี/ค่าลดหย่อน แยกตามปีภาษี  ← แก้ที่นี่ที่เดียวเวลาอัตราเปลี่ยน
  js/engine.js               เอนจินคำนวณบริสุทธิ์ ไม่มี DOM ไม่มี I/O
  js/store.js                IndexedDB (เก็บหลายเคส + สำรอง/นำกลับเป็น JSON)
  js/import-dbd.js           ตัวอ่านไฟล์ DBD และตัวแกะข้อความหน้าข้อมูลนิติบุคคล
  js/ui-kit.js               ตัวช่วยสร้าง DOM + ผูกช่องกรอกเข้ากับข้อมูลเคส
  js/app.js                  แกนแอป: สถานะ, แท็บ, แถบตรวจสอบ, การบันทึก
  js/ui-*.js                 หนึ่งไฟล์ต่อหนึ่งแท็บ (cases, company, pl, bs, comp, taccount, rates, gross, summary, print)
  vendor/xlsx.full.min.js    SheetJS 0.18.5 วางไว้ในโปรเจค — ไม่โหลดจาก CDN ตอนรัน
  test/engine.test.js        ชุดทดสอบ รันด้วย node เปล่า ๆ
  manifest.webmanifest, sw.js, icons/
```

**สามชั้นแยกขาดจากกัน**: ตารางอัตราภาษีรายปี (`tax-tables.js`) → เอนจิน (`engine.js`) → ชั้นหน้าจอ (`ui-*.js`)
เอนจินไม่ฝังอัตราภาษีของตัวเองเลย และหน้าจอไม่คำนวณภาษีเอง

## 2. รันทดสอบ

```bash
node app/www/keyman/test/engine.test.js     # 154 ข้อ — เอนจินคำนวณ
node app/www/keyman/test/import.test.js     # 75 ข้อ — ตัวอ่านไฟล์ DBD และตัวแกะข้อความข้อมูลนิติบุคคล
node app/dev-server.js                      # เปิด http://localhost:5522/keyman/
```

`import.test.js` สร้างไฟล์ .xlsx จำลองในหน่วยความจำด้วย SheetJS ตัวเดียวกับที่แอปใช้ (ไม่ต้องเก็บงบการเงินของลูกค้าไว้ในโปรเจค)
แล้วตรวจครบทุกกับดัก: แยกชนิดไฟล์จาก A1, ปฏิเสธเมื่อชื่อบริษัทสองไฟล์ไม่ตรงกัน, หยิบ 3 ปีล่าสุดจาก 5 ปี,
ชื่อพ้อง "บริหาร"/"บริการ", ค่าว่างเป็น null ไม่ใช่ 0 และการแกะข้อความข้อมูลนิติบุคคลทั้งแบบ copy จากหน้าเว็บและจาก PDF

ชุดทดสอบเอนจินครอบคลุมตัวเลขจากแฟ้ม Excel จริงทุกตัว: อัตราภาษีบุคคล 8 จุด, ภาษีทุกทอด 4 เคส
(รวมเคสที่เงินได้ข้ามขั้น 25%→30% ระหว่างวน), ป.96/2543 ทั้งสองวิธี, สถานะ SME, ค่าใช้จ่ายต้องห้าม
(รวมเคสที่ค่าดิบติดลบและเคสกำไร 2.87 บาท), เพดานเบี้ย, Before/After และกฎตรวจสอบ CHK-01…CHK-12

## 3.1 การจัดสรรเบี้ยรายกรรมการ

ไฟล์ Excel คิดเบี้ยเฉลี่ยต่อคนที่ `งบกำไรขาดทุน!C22 = C18 ÷ C21` แล้วทั้งชีตค่าตอบแทนกรรมการ
(`E7 = งบกำไรขาดทุน!C22`) และชีตภาษีทุกทอด (`F8 = งบกำไรขาดทุน!C22`) ดึงค่านั้นไปใช้ต่อ
แอปทำแบบเดียวกันใน **โหมด "เฉลี่ยเท่ากันทุกท่าน" (ค่าตั้งต้น)** — พิมพ์เบี้ยรวมที่เดียว
แล้วแท็บ 4 กับแท็บ 7 ได้ตัวเลขทันที เศษสตางค์ไปรวมที่ท่านสุดท้ายเพื่อให้ยอดจัดสรรรวมตรงกับเบี้ยรวมเป๊ะ
(ไม่งั้น CHK-06 จะบล็อก)

สลับเป็น **โหมด "จัดสรรรายคนเอง"** ได้ที่แท็บ 1 หรือแท็บ 2 เมื่อจัดสรรไม่เท่ากันตามระดับตำแหน่ง
— โหมดนี้ช่องเบี้ยรายคนกลับมาเป็นช่องกรอกสีเหลือง และยอดรวมต้องเท่ากับเบี้ยรวมพอดีเอง

## 3.2 ฐานคิดเบี้ยประกัน — กฎเหล็กเรื่องถ้อยคำ

**ทุกข้อความที่อธิบายที่มาของเบี้ย ต้องอ้างฐานเดียวคือ "ค่าใช้จ่ายในการขายและบริการ" เท่านั้น**
ห้ามมีคำว่ารายได้ ยอดขาย หรือกำไร ในการบอกว่าเบี้ยคิดมาจากอะไร — ทั้งบนหน้าจอ แถบ CHK และใบเสนอ
(เหตุผล: เบี้ยคีย์แมนถูกบันทึกลงบรรทัดนี้จริง และตัวเลข "5% ของรายได้" ที่ลอยอยู่ในตลาดไม่มีในประมวลรัษฎากร
เว็บเฉพาะทางเองก็เตือนว่าการเสนอเบี้ยเต็มเพดานที่คำนวณจากรายได้คือความผิดพลาดที่ตัวแทนทำกันบ่อย)

`recommendPremium()` ทำงานสองชั้น:

1. **ช่วงเบี้ยจากฐาน** — ฐาน = ค่าที่ต่ำกว่าระหว่างค่าใช้จ่ายในการขายและบริการปีล่าสุดกับเฉลี่ย 3 ปี
   แล้วเสนอ 3 ระดับ: ระมัดระวัง 8% · แนะนำ 10% · สูงสุดที่อธิบายได้ 12%
   (ช่วงนี้มาจากเคสจริงในแฟ้มเดิมที่เกาะกลุ่มกันที่ 8.6–9.5%)
2. **เพดานของเคสนี้** — บีบด้วยตัวคุม 4 ตัว แล้วเอาค่าต่ำสุด: สัดส่วนต่อฐาน (ไม่เกิน 20% เมื่อรวมภาษีที่บริษัทออกให้) ·
   ฐานะการเงินของกิจการ · ความสามารถรองรับรายจ่ายของปีล่าสุด · ค่าตอบแทนรายกรรมการ (เบี้ยต่อท่านไม่เกินค่าจ้างทั้งปี)

ตัวคุมสองตัวกลางคำนวณจากบรรทัดอื่นในงบ **แต่ต้องแปลงเป็น % ของฐานค่าใช้จ่ายในการขายและบริการก่อนแสดงเสมอ**
ผู้ใช้จึงเห็นสัดส่วนของฐานเดียวตลอดทั้งแอป และรู้ว่าตัวไหนเป็นตัวบีบ

## 4. จุดที่ทำ *ต่างจาก* ไฟล์ Excel เดิมโดยตั้งใจ (ห้ามแก้กลับ)

1. **ค่าใช้จ่ายต้องห้ามไม่พังเมื่อบริษัทไม่มีกำไร** — ไฟล์เดิมไม่กันค่าติดลบ ทำให้บริษัทที่ขาดทุน
   และเสียภาษี 0 บาท ได้ "คชจ.ต้องห้าม" สามแสนกว่าบาท ที่นี่คืน 0 พร้อมคำอธิบายแทน
2. **ผลประหยัดภาษีคำนวณด้วย `citTax(กำไร) − citTax(กำไร − รายจ่าย)` สองครั้ง** ไม่ใช่คูณอัตราเดียว
   (กำไร 4,000,000 หัก 2,000,000 แบบ SME ประหยัดจริง 350,000 ไม่ใช่ 400,000)
3. **ภาษีเงินปันผลฝั่ง Before คิดจากกำไรหลังหักภาษีนิติบุคคล** ไม่ใช่จากยอดเต็ม
4. **เบี้ยเกินเพดานมีอะไรเตือน** — CHK-02 บล็อกเมื่อเบี้ยเกิน 5% ของรายได้เฉลี่ย 3 ปี
5. **ระบบตัดสินสถานะ SME เอง** จากทุนชำระแล้วและรายได้ ผู้ใช้เลือกเทมเพลตเองไม่ได้
6. **ตารางอัตราภาษีแก้ช่วงให้ถูกกฎหมาย** — เติม 30% ที่ช่วง 3,000,001–5,000,000 (D13 เดิมว่าง)
   และเลื่อนคอลัมน์ SME ให้ตรงแถว (ยกเว้นถึง 300,000 · 15% ถึง 3,000,000)

## 5.1 ทำไมถึงไม่มีปุ่ม "วางลิงก์แล้วดึงข้อมูลเอง"

หน้าเว็บที่รันบนโดเมนเราอ่านเนื้อหาของ `datawarehouse.dbd.go.th` ตรง ๆ ไม่ได้ — เบราว์เซอร์บล็อก
การอ่านข้ามโดเมน (CORS) ถ้าปลายทางไม่ได้ส่ง header อนุญาต และหน้าโปรไฟล์ของ DBD ยังต้องล็อกอิน
กับวาดข้อมูลด้วย JavaScript อีกชั้น ยิงจากเซิร์ฟเวอร์เฉย ๆ ก็ได้แค่หน้าเปล่า ส่วนการตั้งตัวกลาง
(Cloud Functions) ต้องเปิดแพลน Blaze ซึ่งเจ้าของโปรเจคเลี่ยงไว้ตั้งแต่ต้น

ทางที่ใช้แทนคือ **copy ข้อความจากหน้าเว็บมาวาง** ซึ่งตัวแกะข้อความรองรับทั้งสามรูปแบบที่เจอจริง
(หน้าเว็บแบบไม่มี ":" · แบบมี ":" · ข้อความจาก PDF) และวางลิงก์ต่อท้ายมาด้วยได้เพื่อให้ระบบ
ดึงเลขทะเบียนนิติบุคคล 13 หลักจาก URL ให้เอง

## 6. ข้อจำกัดที่ต้องรู้

- ตัวอ่านไฟล์ DBD ทดสอบกับไฟล์ส่งออกจริงของ DBD DataWarehouse+ แล้ว (งบกำไรขาดทุน + งบแสดงฐานะการเงิน 5 ปี)
  ถ้าเจอไฟล์ที่โครงต่างจากนี้ (เช่นมีแถวใหม่ที่ระบบไม่รู้จัก) หน้ายืนยันจะบอกไว้ท้ายตารางว่าข้ามแถวไหนไป
- ข้อมูลเคสอยู่ใน **IndexedDB ของเบราว์เซอร์นี้ เครื่องนี้** เท่านั้น ล้างข้อมูลเว็บ = หายหมด
  → กด "สำรองข้อมูลเป็นไฟล์ JSON" เป็นระยะ (ปุ่มอยู่หน้าแรก)
- ไม่มีการซิงก์ข้ามเครื่อง และไม่มีการส่งข้อมูลขึ้นเซิร์ฟเวอร์เลย (ตั้งใจ — งบการเงินลูกค้าไม่ควรลอยอยู่บนคลาวด์โดยไม่จำเป็น)
- ตัวเลขทุกตัวเป็นการประมาณเพื่อการนำเสนอ ไม่ใช่คำวินิจฉัยทางภาษี ต้องให้ผู้สอบบัญชีหรือที่ปรึกษาภาษี
  ของบริษัทนั้นตรวจก่อนใช้จริงเสมอ
- เพดาน "เบี้ยไม่เกิน 5% ของรายได้" **ไม่มีในประมวลรัษฎากร** เป็นแนวปฏิบัติของตลาด ระบบใช้เป็นขีดที่ห้ามเกิน
  ไม่ใช่ตัวเลขที่เอาไปเสนอ
