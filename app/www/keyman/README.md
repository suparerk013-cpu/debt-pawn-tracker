# สมุดงานประกันคีย์แมน (PWA)

เว็บแอปสำหรับตัวแทนประกันชีวิต ใช้คำนวณเบี้ยประกันคีย์แมนที่เหมาะกับลูกค้านิติบุคคล
และตรวจว่าโครงสร้างที่เสนอสอดคล้องกับหลักเกณฑ์ของกรมสรรพากรหรือไม่ — ยก Excel เดิม 8 ชีต
ขึ้นเว็บทั้งแผง แถวเดิม คอลัมน์เดิม ลำดับเดิม

**เปิดใช้งานออนไลน์:** https://debt-pawn-tracker-cc106.web.app/keyman/
(เปิดจากมือถือแล้วกด "เพิ่มไปยังหน้าจอโฮม" ใช้งานได้เหมือนแอปจริง และใช้ได้ครบแม้ไม่มีเน็ต)

---

## 1. โครงไฟล์

```
app/www/keyman/
  index.html                 โครงหน้าเดียว โหลดสคริปต์ทั้งหมด
  css/app.css                ธีมสว่าง/มืดผ่าน CSS custom properties
  js/tax-tables.js           ตารางอัตราภาษี/ค่าลดหย่อน แยกตามปีภาษี  ← แก้ที่นี่ที่เดียวเวลาอัตราเปลี่ยน
  js/engine.js               เอนจินคำนวณบริสุทธิ์ ไม่มี DOM ไม่มี I/O
  js/store.js                IndexedDB (เก็บหลายเคส + สำรอง/นำกลับเป็น JSON)
  js/import-dbd.js           ตัวอ่านไฟล์ DBD และตัวแกะข้อความหน้าข้อมูลนิติบุคคล
  js/ui-kit.js               ตัวช่วยสร้าง DOM + ผูกช่องกรอกเข้ากับข้อมูลเคส
  js/app.js                  แกนแอป: สถานะ, แท็บ, แถบตรวจสอบ, การบันทึก
  js/ui-*.js                 หนึ่งไฟล์ต่อหนึ่งแท็บ (cases, company, pl, bs, comp, taccount, rates, gross, summary, print)
  vendor/xlsx.full.min.js    SheetJS 0.18.5 วางไว้ในโปรเจค — ไม่โหลดจาก CDN ตอนรัน
  test/engine.test.js        ชุดทดสอบ รันด้วย node เปล่า ๆ
  manifest.webmanifest, sw.js, icons/
```

**สามชั้นแยกขาดจากกัน**: ตารางอัตราภาษีรายปี (`tax-tables.js`) → เอนจิน (`engine.js`) → ชั้นหน้าจอ (`ui-*.js`)
เอนจินไม่ฝังอัตราภาษีของตัวเองเลย และหน้าจอไม่คำนวณภาษีเอง

## 2. รันทดสอบ

```bash
node app/www/keyman/test/engine.test.js     # 154 ข้อ — เอนจินคำนวณ
node app/www/keyman/test/import.test.js     # 75 ข้อ — ตัวอ่านไฟล์ DBD และตัวแกะข้อความข้อมูลนิติบุคคล
node app/dev-server.js                      # เปิด http://localhost:5522/keyman/
```

`import.test.js` สร้างไฟล์ .xlsx จำลองในหน่วยความจำด้วย SheetJS ตัวเดียวกับที่แอปใช้ (ไม่ต้องเก็บงบการเงินของลูกค้าไว้ในโปรเจค)
แล้วตรวจครบทุกกับดัก: แยกชนิดไฟล์จาก A1, ปฏิเสธเมื่อชื่อบริษัทสองไฟล์ไม่ตรงกัน, หยิบ 3 ปีล่าสุดจาก 5 ปี,
ชื่อพ้อง "บริหาร"/"บริการ", ค่าว่างเป็น null ไม่ใช่ 0 และการแกะข้อความข้อมูลนิติบุคคลทั้งแบบ copy จากหน้าเว็บและจาก PDF

ชุดทดสอบเอนจินครอบคลุมตัวเลขจากแฟ้ม Excel จริงทุกตัว: อัตราภาษีบุคคล 8 จุด, ภาษีทุกทอด 4 เคส
(รวมเคสที่เงินได้ข้ามขั้น 25%→30% ระหว่างวน), ป.96/2543 ทั้งสองวิธี, สถานะ SME, ค่าใช้จ่ายต้องห้าม
(รวมเคสที่ค่าดิบติดลบและเคสกำไร 2.87 บาท), เพดานเบี้ย, Before/After และกฎตรวจสอบ CHK-01…CHK-12

## 3.1 การจัดสรรเบี้ยรายกรรมการ

ไฟล์ Excel คิดเบี้ยเฉลี่ยต่อคนที่ `งบกำไรขาดทุน!C22 = C18 ÷ C21` แล้วทั้งชีตค่าตอบแทนกรรมการ
(`E7 = งบกำไรขาดทุน!C22`) และชีตภาษีทุกทอด (`F8 = งบกำไรขาดทุน!C22`) ดึงค่านั้นไปใช้ต่อ
แอปทำแบบเดียวกันใน **โหมด "เฉลี่ยเท่ากันทุกท่าน" (ค่าตั้งต้น)** — พิมพ์เบี้ยรวมที่เดียว
แล้วแท็บ 4 กับแท็บ 7 ได้ตัวเลขทันที เศษสตางค์ไปรวมที่ท่านสุดท้ายเพื่อให้ยอดจัดสรรรวมตรงกับเบี้ยรวมเป๊ะ
(ไม่งั้น CHK-06 จะบล็อก)

สลับเป็น **โหมด "จัดสรรรายคนเอง"** ได้ที่แท็บ 1 หรือแท็บ 2 เมื่อจัดสรรไม่เท่ากันตามระดับตำแหน่ง
— โหมดนี้ช่องเบี้ยรายคนกลับมาเป็นช่องกรอกสีเหลือง และยอดรวมต้องเท่ากับเบี้ยรวมพอดีเอง

## 3.2 ฐานคิดเบี้ยประกัน — กฎเหล็กเรื่องถ้อยคำ

**ทุกข้อความที่อธิบายที่มาของเบี้ย ต้องอ้างฐานเดียวคือ "ค่าใช้จ่ายในการขายและบริการ" เท่านั้น**
ห้ามมีคำว่ารายได้ ยอดขาย หรือกำไร ในการบอกว่าเบี้ยคิดมาจากอะไร — ทั้งบนหน้าจอ แถบ CHK และใบเสนอ
(เหตุผล: เบี้ยคีย์แมนถูกบันทึกลงบรรทัดนี้จริง และตัวเลข "5% ของรายได้" ที่ลอยอยู่ในตลาดไม่มีในประมวลรัษฎากร
เว็บเฉพาะทางเองก็เตือนว่าการเสนอเบี้ยเต็มเพดานที่คำนวณจากรายได้คือความผิดพลาดที่ตัวแทนทำกันบ่อย)

`recommendPremium()` ทำงานสองชั้น:

1. **ช่วงเบี้ยจากฐาน** — ฐาน = ค่าที่ต่ำกว่าระหว่างค่าใช้จ่ายในการขายและบริการปีล่าสุดกับเฉลี่ย 3 ปี
   แล้วเสนอ 3 ระดับ: ระมัดระวัง 8% · แนะนำ 10% · สูงสุดที่อธิบายได้ 12%
   (ช่วงนี้มาจากเคสจริงในแฟ้มเดิมที่เกาะกลุ่มกันที่ 8.6–9.5%)
2. **เพดานของเคสนี้** — บีบด้วยตัวคุม 4 ตัว แล้วเอาค่าต่ำสุด: สัดส่วนต่อฐาน (ไม่เกิน 20% เมื่อรวมภาษีที่บริษัทออกให้) ·
   ฐานะการเงินของกิจการ · ความสามารถรองรับรายจ่ายของปีล่าสุด · ค่าตอบแทนรายกรรมการ (เบี้ยต่อท่านไม่เกินค่าจ้างทั้งปี)

ตัวคุมสองตัวกลางคำนวณจากบรรทัดอื่นในงบ **แต่ต้องแปลงเป็น % ของฐานค่าใช้จ่ายในการขายและบริการก่อนแสดงเสมอ**
ผู้ใช้จึงเห็นสัดส่วนของฐานเดียวตลอดทั้งแอป และรู้ว่าตัวไหนเป็นตัวบีบ

## 4. จุดที่ทำ *ต่างจาก* ไฟล์ Excel เดิมโดยตั้งใจ (ห้ามแก้กลับ)

1. **ค่าใช้จ่ายต้องห้ามไม่พังเมื่อบริษัทไม่มีกำไร** — ไฟล์เดิมไม่กันค่าติดลบ ทำให้บริษัทที่ขาดทุน
   และเสียภาษี 0 บาท ได้ "คชจ.ต้องห้าม" สามแสนกว่าบาท ที่นี่คืน 0 พร้อมคำอธิบายแทน
2. **ผลประหยัดภาษีคำนวณด้วย `citTax(กำไร) − citTax(กำไร − รายจ่าย)` สองครั้ง** ไม่ใช่คูณอัตราเดียว
   (กำไร 4,000,000 หัก 2,000,000 แบบ SME ประหยัดจริง 350,000 ไม่ใช่ 400,000)
3. **ภาษีเงินปันผลฝั่ง Before คิดจากกำไรหลังหักภาษีนิติบุคคล** ไม่ใช่จากยอดเต็ม
4. **เบี้ยเกินเพดานมีอะไรเตือน** — CHK-02 บล็อกเมื่อเบี้ยเกิน 5% ของรายได้เฉลี่ย 3 ปี
5. **ระบบตัดสินสถานะ SME เอง** จากทุนชำระแล้วและรายได้ ผู้ใช้เลือกเทมเพลตเองไม่ได้
6. **ตารางอัตราภาษีแก้ช่วงให้ถูกกฎหมาย** — เติม 30% ที่ช่วง 3,000,001–5,000,000 (D13 เดิมว่าง)
   และเลื่อนคอลัมน์ SME ให้ตรงแถว (ยกเว้นถึง 300,000 · 15% ถึง 3,000,000)

## 6. ข้อจำกัดที่ต้องรู้

- ตัวอ่านไฟล์ DBD ทดสอบกับไฟล์ส่งออกจริงของ DBD DataWarehouse+ แล้ว (งบกำไรขาดทุน + งบแสดงฐานะการเงิน 5 ปี)
  ถ้าเจอไฟล์ที่โครงต่างจากนี้ (เช่นมีแถวใหม่ที่ระบบไม่รู้จัก) หน้ายืนยันจะบอกไว้ท้ายตารางว่าข้ามแถวไหนไป

  → กด "สำรองข้อมูลเป็นไฟล์ JSON" เป็นระยะ (ปุ่มอยู่หน้าแรก)
- ไม่มีการซิงก์ข้ามเครื่อง และไม่มีการส่งข้อมูลขึ้นเซิร์ฟเวอร์เลย (ตั้งใจ — งบการเงินลูกค้าไม่ควรลอยอยู่บนคลาวด์โดยไม่จำเป็น)
- ตัวเลขทุกตัวเป็นการประมาณเพื่อการนำเสนอ ไม่ใช่คำวินิจฉัยทางภาษี ต้องให้ผู้สอบบัญชีหรือที่ปรึกษาภาษี
  ของบริษัทนั้นตรวจก่อนใช้จริงเสมอ
- เพดาน "เบี้ยไม่เกิน 5% ของรายได้" **ไม่มีในประมวลรัษฎากร** เป็นแนวปฏิบัติของตลาด ระบบใช้เป็นขีดที่ห้ามเกิน
  ไม่ใช่ตัวเลขที่เอาไปเสนอ

## 7. หน้าสรุปผลต่าง (แท็บ 8)

เรียงจากคำตอบไปหาที่มา: แถบคำตอบ → การ์ดสองฝั่ง After/Before → สามบล็อกเปรียบเทียบ →
ตารางเต็มและข้อควรระวังที่พับเก็บไว้ใน `<details class="fold">`

การ์ดสองฝั่งมีแถวเท่ากันฝั่งละ 5 แถว + แถวรวม เรียงตรงกันบรรทัดต่อบรรทัดตามชีตเดิม
(เบี้ยประกัน ↔ เงินส่วนกำไร · ภาษีทุกทอด ↔ ภาษีบุคคล · ค่าใช้จ่ายรวม ↔ – ·
ประหยัดภาษีนิติ ↔ ภาษีนิติบุคคล · ภาษีเงินปันผล ↔ ภาษีเงินปันผล · เสียภาษีรวม)

หน้าจอวางเป็นสองคอลัมน์ตลอดทั้งหน้าเหมือนชีตเดิม (After ซ้าย / Before ขวา) แต่ละบล็อกปิดท้าย
ด้วยแถบ "ผลต่าง" คั่นกลางแทนช่องเขียว/น้ำเงินของชีต บล็อกที่ 2 และ 3 มีแถบวัดบาง ๆ ใต้ตัวเลข
ใช้สเกลร่วมกันภายในบล็อก จะได้เห็นสัดส่วนโดยไม่ต้องอ่านเลข

สี่บล็อกเปรียบเทียบตามชีตเดิมทุกบล็อก: ภาษีที่เสียรวม · เงินเดือนและโบนัสที่กรรมการ
รับจริง (`comparison.after.directorNet` = เงินเดือนรวมเต็มเพราะบริษัทออกภาษีให้,
`before.directorNet` = เงินเดือนรวม − ภาษีบุคคล) · เงินเข้าเจ้าของทั้งหมด
ชีตเดิมคิด % ของแต่ละบล็อกจากฐานคนละตัว (บล็อกแรกคิดจากเบี้ย บล็อกที่สามคิดจากฝั่ง Before)
ที่นี่ใช้ฐานเดียวกันทุกบล็อกคือ**ฝั่งปันผล** และเขียนกำกับไว้บนหัวการ์ด
บล็อก 4 "ขอคืนภาษีบุคคลธรรมดา" ในไฟล์เดิมเป็นช่องว่างให้กรอกเอง (สูตรจึงคืน `#DIV/0!`)
แอปทำเป็นช่องกรอกสองฝั่งเหมือนกัน เก็บที่ `policy.refundAfter` / `policy.refundBefore`
ถ้ายังไม่กรอกทั้งสองฝั่ง แถบผลต่างจะบอกว่า "ยังไม่ได้กรอกทั้งสองฝั่ง" ไม่ใช่โชว์ 0 หรือ `#DIV/0!`

บล็อก 2 เขียนการลบให้เห็นเลขบนฝั่งปันผล ("เงินเดือนเต็ม X − ภาษีหัก ณ ที่จ่าย Y") และถ้า
ภาษีเป็นศูนย์ — เกิดได้จริงเมื่อกรรมการหลายท่านมีเงินเดือนคนละไม่ถึงเกณฑ์ — จะเขียนบอกว่า
ไม่ถึงเกณฑ์เสียภาษี ไม่ใช่ปล่อยให้เห็นเลขซ้ำกันสองฝั่งแล้วนึกว่าระบบลืมหัก

สีสองเส้นของกราฟ (`--s1` น้ำเงิน = ทำคีย์แมน, `--s2` ส้ม = ปันผล) ผ่านการตรวจ contrast และ
colour-blind separation มาแล้วทั้งโหมดสว่างและมืด **ถ้าจะเปลี่ยนสีต้องตรวจซ้ำก่อน** — คู่นี้ห่างกัน
ΔE 24.7 (protan) / 33.6 (normal vision) บนพื้นขาว และ 26.8 / 31.8 บนพื้นมืด

## 8. สายเชื่อมระหว่างชีตภาษีบุคคลกับชีตสรุป

ชีต "Excel ช่วยคำนวณภาษีเงินได้บุคคลธรรมดา" ป้อนเลขสองตัวเข้าชีตสรุปโดยตรง —
คอลัมน์แรก (เงินเดือนอย่างเดียว) เป็น `before.personalTax` และคอลัมน์สุดท้าย
(ออกภาษีให้จนลู่เข้า) เป็น `after.allTierTax` เทสต์ชุด "สายเชื่อมจากชีตภาษีบุคคล
เข้าชีตสรุป" ป้อนผลจาก `grossUpTax` เข้า `compareScenarios` ตรง ๆ ห้ามใส่เลขมือ
เพื่อไม่ให้สองฝั่งแยกกันเพี้ยนโดยไม่มีใครรู้

ตรวจกับไฟล์จริงแล้วตรงทุกช่องฝั่ง After (185,000 · 749,000 · 1,070,000 ·
3,070,000 · 614,000 · 456,000 · 1,440,000 · 1,255,000 · 3,440,000)

**สองช่องที่ตั้งใจคิดต่างจากไฟล์เดิม** ทั้งคู่อยู่ฝั่ง Before:

| ช่อง | ไฟล์เดิม | แอป | เหตุผล |
|---|---|---|---|
| ภาษีเงินปันผล | 200,000 (10% ของ 2,000,000) | 160,000 (10% ของ 2,000,000 − 400,000) | ปันผลจ่ายได้จากกำไรหลังภาษีเท่านั้น |
| เงินเข้าเจ้าของ | 3,055,000 | 2,695,000 | ไฟล์เดิมนับภาษีนิติ 400,000 เป็นภาษีที่เสีย แต่ยังแจกเงินให้เจ้าของเหมือนไม่เคยจ่าย |

ผลคือฝั่ง Before ของไฟล์เดิมดูดีเกินจริง 400,000 บาท ซึ่งทำให้ฝั่งทำคีย์แมนเสียเปรียบ

## 9. แท็บ 7 ภาษีทุกทอด — ตรงกับชีตต้นฉบับ

หน้าจอวางตามชีต "ช่วยคำนวณภาษีเงินได้บุคคลธรรมดา" ทุกส่วน: ประเภทเงินได้ →
หักค่าใช้จ่าย 50% (ไม่เกิน 100,000) → รายการค่าลดหย่อน B15–B33 **ครบทั้ง 19 แถวเป็น
ค่าเริ่มต้น** → ส่วนของเงินบริจาค B38–B39 → เงินได้สุทธิ → ภาษีที่เสีย → อัตราภาษีที่แท้จริง
→ ตารางสรุปการบันทึกค่าใช้จ่าย แถว 44–49

สีเซลล์ยึดธรรมเนียมไฟล์เดิม: แถวรวม = อำพัน · ภาษีที่เสียทอดที่ยังไม่จบ = เขียว ·
ทอดสุดท้าย = แดง · อัตราภาษี = พีช (กฎ `tr.total > td` เคยกลบสีพวกนี้ ต้องมีกฎเฉพาะ
`tr.total > td.tax-final` ฯลฯ ทับไว้ อย่าลบออก)

**เพดานค่าลดหย่อนรายกลุ่มเป็นเพดานจริง** ชีตต้นฉบับครอบไว้ด้วยสูตร MIN() และตาม
กฎหมายส่วนที่เกินก็หักไม่ได้ `sumAllowances` จึงคืน `total` เป็นยอดหลังตัดเพดาน
(`rawTotal` คือยอดที่ผู้ใช้กรอก, `groups` ยอดดิบรายกลุ่ม, `groupsCounted` ยอดหลังตัด)
หน้าจอตีเส้นสีคร่อมแถวในกลุ่มแล้วปิดท้ายด้วยแถวยอดรวมกลุ่ม ซึ่งเปลี่ยนเป็นแดงพร้อม
บอก "หักได้จริง X" เมื่อเกิน CHK-12 ยังเตือนเหมือนเดิมแต่เปลี่ยนข้อความเป็นบอกว่า
ระบบหักให้ตามเพดานแล้ว

## 10. เกณฑ์ SME ทางภาษี — ตัดสินจากอะไร

สองเงื่อนไข ต้องเข้าทั้งคู่ (เกินข้อใดข้อหนึ่งแม้บาทเดียว = ไม่ใช่ SME → 20% ตั้งแต่บาทแรก):

| เงื่อนไข | เพดาน | ค่าที่ใช้ |
|---|---|---|
| ทุนจดทะเบียนที่ชำระแล้ว | ไม่เกิน 5,000,000 | `company.paidUpCapital` |
| ยอดขายสินค้าและบริการ | ไม่เกิน 30,000,000 | `financials.mainRevenue` ปีล่าสุด |

`smeRevenue(financials)` เลือกฐานให้: ใช้ **รายได้หลัก (ยอดขาย)** ก่อน ถ้ายังไม่ได้กรอก
จึงถอยไปใช้ **รายได้รวม** แล้วขึ้นหมายเหตุบอก เพราะรายได้รวมมีรายได้อื่น (ดอกเบี้ยรับ
กำไรจากการขายทรัพย์สิน เงินปันผลรับ) ปนอยู่ ซึ่งกฎหมายไม่ได้นับในเกณฑ์นี้ — ถ้าใช้
รายได้รวมตัดสินจะเข้มกว่าเกณฑ์จริงและอาจตีว่าไม่ใช่ SME ทั้งที่ยังเป็น

**ขนาดธุรกิจ S/M/L ของ DBD ไม่มีผลต่อการคำนวณใด ๆ** `company.sizeLabel` ถูกอ่านเข้ามา
และแสดงบนหน้าจอเท่านั้น ไม่มีสูตรไหนอ่านค่านี้ — มีเทสต์ยืนยันว่าเปลี่ยน S เป็น L แล้ว
ผลตัดสิน SME ไม่เปลี่ยน

## 11. ช่องกรอกและช่องอัปโหลด

`K.dropzone({ accept, multiple, icon, title, hint, onFiles })` คือช่องอัปโหลดกลาง ใช้ทั้ง
การนำเข้า .xlsx จาก DBD และการนำไฟล์สำรอง .json กลับเข้า — ลากไฟล์มาวาง กดที่กรอบ หรือ
กด Enter/Space ก็ได้ `input[type=file]` จริงซ่อนไว้เพราะหน้าตาคนละเรื่องกับทั้งแอป

รายละเอียดที่ต้องระวังถ้าจะแก้:
- `dragenter`/`dragleave` ยิงซ้ำทุกครั้งที่ลากผ่านลูก ๆ ข้างใน ต้องนับชั้น (`depth`) เอง
  ไม่งั้นกรอบจะกะพริบ
- เบราว์เซอร์จะ **เปิดไฟล์แทนหน้าเว็บ** ถ้าปล่อยวางนอกกรอบ จึงกัน `dragover`/`drop`
  ที่ระดับ document ไว้ครั้งเดียว (`guardDocumentDrop`)
- กรองนามสกุลเองจาก `accept` เพราะการลากวางไม่ผ่านตัวกรองของ `input[type=file]`
  ไฟล์ผิดชนิดจะขึ้นกล่องบอกว่ารับอะไรได้บ้างและข้ามไฟล์ไหนไป

ช่องกรอกยังใช้ธรรมเนียมสีของ Excel (เหลือง = กรอกได้ · เทา = สูตร) แต่โทนเหลืองอ่อนลง
เป็น `#fffbea` ให้จ้องได้นาน สูงขั้นต่ำ 36px (ในตาราง 32px) โฟกัสเปลี่ยนขอบเป็นสีแอ็กเซนต์

## 13. แท็บ 2 การ์ดค่าใช้จ่ายต้องห้าม (CHK-04)

ตารางนี้ไม่ได้เห็นรายการรายจ่ายจริง มันเห็นแค่กำไรก่อนภาษีกับภาษีที่จ่าย แล้ว **ถอดกลับ**:

```
ฐานภาษี      = citTax(กำไรก่อนภาษี, isSme, ปีภาษี)
ส่วนเกินภาษี   = ภาษีที่จ่ายจริง − ฐานภาษี
คชจ.ต้องห้าม  = ส่วนเกินภาษี ÷ citMarginalRate(กำไรก่อนภาษี, isSme, ปีภาษี)
```

จึงเป็น **ประมาณการ** ไม่ใช่ตัวเลขจาก ภ.ง.ด.50 ทุกแถวในตารางมีบรรทัดบอกที่มาใต้ชื่อแถว
และเพิ่มแถว "อัตราตามกฎหมายของกำไรก้อนท้าย" ให้เห็นตัวหาร ซึ่งเดิมไม่ได้แสดงที่ไหนเลย
ทั้งที่เป็นตัวกำหนดคำตอบ

สถานะรายปีแสดงเป็นรายการทีละปี (`ul.whylist`) ไม่ยุบเป็นข้อความเดียว — สี่กรณีที่คิดไม่ได้:
กรอกไม่ครบ · ปีนั้นขาดทุน · กำไรอยู่ในช่วงยกเว้น 300,000 แรกของ SME (อัตราส่วนเพิ่ม = 0
หารไม่ได้) · จ่ายภาษีน้อยกว่าฐาน (ผลขาดทุนสะสมยกมา สิทธิ BOI รายได้ยกเว้น เครดิตภาษี)

## 14. เพดานเบี้ยที่ระบบใช้บีบจริง

`recommendPremium` เสนอ 10% ของฐานคิดเบี้ย แล้วบีบด้วยเพดาน 5 ตัว ตัวที่ต่ำที่สุดชนะ:

| key | ชื่อที่แสดง | คิดจาก |
|---|---|---|
| `bookedShare` | สัดส่วนต่อฐาน | ยอดบันทึกรายจ่าย (เบี้ย + ภาษีที่ออกให้) ≤ 20% ของฐานคิดเบี้ย |
| `businessSize` | ขนาดของกิจการโดยรวม | 5% ของยอดขายเฉลี่ย 3 ปี |
| `financial` | ฐานะการเงินของกิจการ | 20% ของกำไรสุทธิ (ค่าที่ต่ำกว่าระหว่างปีล่าสุดกับเฉลี่ย 3 ปี) |
| `solvency` | ความสามารถรองรับรายจ่ายของปีล่าสุด | ยอดบันทึกรายจ่ายต้องไม่เกินกำไรก่อนภาษีปีล่าสุด |
| `perDirector` | ค่าตอบแทนรายกรรมการ | เบี้ยรายคนไม่เกินค่าจ้างทั้งปีของท่านนั้น |

`businessSize` กับ `financial` คือเกณฑ์ตลาด **min(5% ของยอดขาย, 20% ของกำไรสุทธิ)** ที่ทุก
แหล่งอ้างตรงกัน เดิมโค้ดคำนวณสองค่านี้ไว้แล้ว **แต่ไม่ได้เอามาบีบเลย** จึงมีเคสที่ระบบเสนอ
สูงกว่าเพดานตลาด (เคสในเทสต์: เสนอ 400,000 ทั้งที่เพดานอยู่ที่ 250,000)

**กฎถ้อยคำ**: ชื่อและคำอธิบายของเพดานทุกตัว **ห้ามมีคำว่า รายได้ / ยอดขาย / กำไร** และทุก
เพดานต้องมี `pctOfBase` ติดไปด้วย เพราะหน้าจอแสดงได้เฉพาะ % ของฐานคิดเบี้ยเท่านั้น
มีเทสต์ยิง regex คุมทั้งสองข้อไว้แล้ว

`ceilingNetProfit` ใช้ค่าที่ต่ำกว่าระหว่างปีล่าสุดกับเฉลี่ย 3 ปี หลักเดียวกับฐานคิดเบี้ย —
ปีเดียวที่ผลประกอบการเด้งขึ้นต้องไม่ดันเพดานตาม และขาดทุนทุกปีให้เพดานเป็น 0 ไม่ใช่ติดลบ

## 16. ใบเสนอลูกค้า (js/ui-quote.js)

A4 แนวตั้ง เลือกได้ **เต็ม 2 หน้า** หรือ **สั้น 1 หน้า** (`keyman.quoteLength`)

หน้า 1 = ข้อเสนอ (แถบคำตอบ · สามช่องตัวเลข · เทียบสามด้านพร้อมแท่งวัด)
หน้า 2 = การจัดสรรรายกรรมการ · เหตุผลประกอบการเสนอ · เอกสารที่ต้องจัดเก็บ · ข้อควรทราบ · ที่เซ็น

**ที่มาของเบี้ยไม่พิมพ์ลงใบเสนอโดยค่าเริ่มต้น** (`keyman.quoteBasis` = '0') เพราะกระดาษที่ระบุ
ว่าเบี้ยคิดเป็นกี่ % ของบรรทัดไหนในงบ เท่ากับตอบคำถาม "เบี้ยนี้คิดจากไหน" แทนเจ้าของกิจการ
ไปแล้วว่ามาจากสูตร ไม่ใช่มาจากเหตุผลทางธุรกิจ — เปิดได้ด้วยสวิตช์ถ้าจำเป็นต้องใช้คุย

"เหตุผลประกอบการเสนอ" ห้าข้อคือสิ่งที่ปกป้องเบี้ยจริง ๆ ติ๊กจากข้อเท็จจริงที่ตรวจได้:
สามข้อจาก `kase.docs` และอีกสองข้อคำนวณเอง (กรรมการทุกท่านมีเกณฑ์ระดับตำแหน่ง ·
เบี้ยรายคนไม่เกินค่าตอบแทนทั้งปีของท่านนั้น)

**ข้อมูลผู้เสนอ** (ชื่อ เบอร์ อีเมล เลขที่ใบอนุญาต สังกัด โลโก้) เก็บใน `localStorage`
คีย์ `keyman.agent` — เป็นข้อมูลระดับเครื่อง ไม่ผูกกับเคส และ**ไม่ติดไปกับไฟล์สำรองเคส**
โลโก้เก็บเป็น data URL จำกัดไว้ 400 KB ไม่งั้น localStorage เต็ม

ตัวเลขบนใบเสนอปัดเป็นบาทเต็ม สตางค์ไม่ได้ช่วยลูกค้าตัดสินใจ
